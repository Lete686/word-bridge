# 已知问题与验收范围

## K01：墨墨云端已有单词，插件仍显示“失败”

状态：开放，尚未修复验收。

现场已确认：墨墨云词本中可以看到测试词 `political`，而插件生词列表在同步后仍显示失败。v0.1.4 修复了连接参数、响应包装及错误脱敏，没有更改这条核实状态逻辑。

目前不能据此判定是服务器解析延迟、实际返回结构差异，还是本地状态未更新。后续应在用户授权的测试词本中只读检查正文、解析 list 与读回时序；不要用自己提交的正文直接伪造“已核实”。

临时使用方式：在墨墨云词本中核对内容。界面的“本次追加”是合并计划统计，不是云端已收录凭证。云词本有词也不代表该词已进入每日学习计划。

## K02：部分词条没有音标或词形标注不准确

来源词典本身存在缺项。变形词可能有释义与原形但没有音标，个别关系标注也可能不准确。当前浮窗如实显示缺失，不把原形音标当作原词音标，也不按后缀推测原形。

## K03：英文发音依赖系统语音

插件调用 Obsidian 所在浏览器环境的语音接口。Windows 安装了英文语音后，仍需检查应用能否枚举并播放。已有本机案例在彻底退出 Obsidian 旧进程后恢复发音；仅重新打开窗口可能不足以刷新语音列表。

本仓库不分发微软语言包，也不修改系统更新服务、注册表或语音设置。离线语音的安装源应与 Windows 版本和架构匹配。

## K04：全量更新接口没有原子并发保证

墨墨云词本更新使用全量正文。插件有写前重读、重新合并、串行写入和写后核实，也避免在结果未知时重放陈旧载荷；但接口没有条件更新机制，跨客户端同时编辑仍无法获得原子内容保留保证。

## 当前验证范围

- 本地已有 100 项单元测试，覆盖选区、词典、收藏、翻译请求、脱敏和同步状态等逻辑。
- 词本列表读取与部分测试词到达云端已有用户现场反馈；同步状态仍有 K01。
- 英文离线发音在一个 Windows 环境经实际操作恢复；其他 Windows 配置未逐一验证。
- 真实大模型提供商、更多账户、服务端词形处理和延迟行为未形成完整兼容性验收。
- GitHub CI、单元测试与打包检查不等于真实服务或 Obsidian UI 验收。
